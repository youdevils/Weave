# Refresh a published output after model changes

A published OnyxJar view is a snapshot of the model at the time it was created. Editing the source model does not automatically refresh a previously downloaded portable HTML file. If readers need to see your changes, create an updated publication and distribute the newer snapshot.

## When to publish again

Create an updated publication when changes to the source model affect what your audience needs to understand. This may include changes to:

- Objects or their attributes.
- Relationships between objects.
- The overall structure or scope of the model.
- The model description or other information shown to readers.

Not every internal edit requires a new distribution. Consider who uses the published view and whether the change matters to them.

## Create an updated snapshot

1. Open the current source model and confirm that the changes you want to share are saved.
2. Use the publishing option available in the current OnyxJar interface to create a new publication.
3. Open the new published view and check that the intended information is present.
4. If you distribute a portable output, download the updated HTML file.
5. Replace or clearly supersede the file you previously shared, and let recipients know which snapshot is current when that distinction matters.

Use the current interface as the source of truth for the exact controls and available publication options. Downloading a portable file may depend on your account's plan or entitlements.

## Remember that downloaded files do not update themselves

Anyone who already has a portable HTML file still has that original snapshot. Creating a newer publication does not alter copies already saved on other people's devices or sent through email or file sharing.

Choose a clear naming convention, such as including the model revision or publication date, so recipients can distinguish versions. If older snapshots should no longer be used, tell recipients explicitly and remove old copies from shared locations that you control.

## Confirm what you are sharing

Before distributing the update, check that the published information is intended for its audience and that the displayed revision or publication date is consistent with the version you meant to share.

If readers need to inspect the published view, direct them to [Explore a published model](/help/publish-and-share/explore-a-published-model/). If you need a downloadable standalone file, see [Use a portable published output](/help/publish-and-share/use-a-portable-published-output/).
