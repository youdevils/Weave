# Use a portable published output

A portable published output is an interactive, read-only HTML snapshot of an OnyxJar model. It is a file you can share with people who need to explore the model without logging in to edit it. The output is designed to work independently, including offline.

The file represents the model at the time it was published. It is not a live connection to the editable model and will not automatically change when the model changes.

## Get the file

1. Open the model you want to share.
2. Publish the model using the publishing options available in your OnyxJar interface.
3. If a downloadable portable output is available for your account, download the HTML file.
4. Save it with a meaningful filename so you can distinguish it from earlier snapshots. Include a revision or date in the filename if you expect to publish updates regularly.

Downloading may depend on your account's current plan or entitlements. If the download option is not available, use the publication options currently offered to your account.

## Open and share it

Open the downloaded HTML file in a modern web browser. You do not need the normal model-editing interface to explore the portable snapshot, and the file is intended to remain usable without an internet connection.

You can share the file through the same channels you would use for other documents, subject to your organisation's information-handling requirements. Before sending it, remember that the recipient receives a copy of the published model data. Do not distribute it unless the information in that snapshot is appropriate for the audience.

## Explore the snapshot

Readers can explore the graph, search and filter model elements, and inspect available object details and connections. The experience is interactive, but read-only: it does not give the recipient permission to change your source model.

The published header can show identifying information such as the model name, description, revision and publication date. Use those details to help readers recognise which snapshot they have received.

## Keep track of versions

A portable file is a point-in-time copy. If you change the model and want to distribute the new state, create a new publication and download a fresh output. Sending the old file again will still share the old snapshot.

A simple practice is to keep the latest file in a clearly identified location and move older files into an archive rather than overwriting them without a record. See [Refresh a published output after model changes](/help/publish-and-share/refresh-a-published-output-after-model-changes/).
